SPA 形式送信テスト

React や Vue 等のフレームワークが採用しがちな 4 種類の送信パターンです。ID とパスワードを入力して、いずれかのボタンを押してください。

URL は JavaScript で書き換えるだけで、画面遷移は起こさず DOM を差し替える方式（最もモダンな SPA 形式）。submit イベントは発火しないため、テスト対象ブラウザの保存機能では取りこぼされます。

古典的な画面遷移。location.assign で次のページに移動します。submit イベントは発火しないため、テスト対象ブラウザの保存機能では取りこぼされます。

フォームはあるが送信は完全に JavaScript 制御。送信ボタンは type="button" で submit イベントが発火しないため、テスト対象ブラウザの保存機能では取りこぼされます。

送信ボタン押下 → submit イベント発火 → JavaScript で横取りして処理。React 等で典型的な書き方で、テスト対象ブラウザの保存機能でも拾えます。

パターン D: fetch + history.pushState（form 無し、純粋 SPA）
  - submit イベント発火しない

パターン E: location.assign（form 無し、ハード遷移）
  - submit イベント発火しない
  - WKNavigationType=other で WKNavigationDelegate 発火
  - JS submit listener / WKNavigationType フィルタの両方とも検知不可

パターン F: form + 完全 JS 制御（type=button、native submit せず）
  - submit イベント発火しない
  - WKNavigationDelegate も無音（native submit が起きないため）
  - テスト対象ブラウザの保存機能では検知不可

パターン G: form + type=submit + addEventListener で preventDefault（React 典型形）
  - submit イベント発火する
  - WKNavigationDelegate は無音（preventDefault で native navigation 抑止）
  - JS submit listener 方式なら検知可能 ← テスト対象ブラウザの新フローの強み

パターン G が JS injection 経由で保存ダイアログを出せれば、主要ブラウザ相当の網羅率を達成。
