Google 式 2 段階ログインテスト

Google (accounts.google.com) や Microsoft (login.microsoftonline.com) のような、ID を先に入力させ次画面でパスワードを入力させる 2 段階パターンです。

パターン H: ネイティブ 2 画面遷移

HTML の form 送信で次画面 (stepped-password.html) に遷移します。ID と PW が別ページに分かれているため、テスト対象ブラウザの「同ページ完結型」検知では取りこぼされます。

パターン I: SPA 式 2 段階 (同一ページ内で ID → PW)

「次へ」を押すと DOM を差し替えてパスワード入力画面に切り替わり、history.pushState で URL も書き換えます。Google 本家と同型の SPA 式 2 段階。

実装詳細（開発者向け） 
パターン H: ID ページ → PW ページ の別 HTML 遷移
  - ID ページ (stepped.html): username 入力 → 次へ (form submit)
  - PW ページ (stepped-password.html): password 入力 → ログイン (form submit) → success.html
  - readLoginForm.js が「password と username 両方揃わないと null」の設計だと、両ページとも検出失敗
  - 自動入力: PW ページで credential を引くには host 単位の credential lookup が必要
  - 参考: Xamarin は AutofillPass (タッチ契機) で PW 単独ページ用の PW-only 自動入力を持つ

パターン I: 同一ページで DOM 差替 + pushState
  - navigation 発火せず、KVO で url 変化を検知しないと再スキャンできない
  - 現状の実装 (PR #247) は didFinishLoading 契機の readLoginForm のみゆえ、切り替え後の PW 入力欄は検出されない
  - KVO で sameDocumentURLChange を検知する仕掛けは保存側にはあるが、自動入力側は didFinishLoading 限定
