パターン H: ネイティブ 2 画面遷移

ID を先に入力させ、次画面 (stepped-password.html) でパスワードを入力させる 2 段階パターンです。Google (accounts.google.com) や Microsoft (login.microsoftonline.com) が採用する形式のうち、ID 画面と PW 画面が別 HTML に分かれている「ネイティブ遷移式」を再現します。

HTML の form 送信で次画面 (stepped-password.html) に遷移します。ID と PW が別ページに分かれているため、テスト対象ブラウザの「同ページ完結型」検知では取りこぼされます。

同一 URL 内で DOM を差し替える SPA 式 2 段階は パターン I (stepped-spa.html) を参照してください。

実装詳細 
パターン H: ID ページ → PW ページ の別 HTML 遷移
  - ID ページ (stepped.html): username 入力 → 次へ (form submit)
  - PW ページ (stepped-password.html): password 入力 → ログイン (form submit) → success.html
  - readLoginForm.js が「password と username 両方揃わないと null」の設計だと、両ページとも検出失敗
  - 自動入力: PW ページで credential を引くには host 単位の credential lookup が必要
  - 参考: Xamarin は AutofillPass (タッチ契機) で PW 単独ページ用の PW-only 自動入力を持つ
